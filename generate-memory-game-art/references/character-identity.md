# 人物参考图身份还原规范

人物参考图存在时必须完整读取本文件。目标是把真实人物转换为适合互动回忆小游戏的二维插画角色，同时保留一眼可区分的个人身份；不得只把照片当作服装或发型参考。

## 1. 区分两种模式

- `PHOTO_TO_GAME_ART`：用户要求把上传照片本身转为游戏插画。人物参考图决定身份、人数、左右关系、姿态、表情和亲密关系；场景描述只补充未显示的信息。
- `IDENTITY_IN_NEW_SCENE`：用户要求把照片人物放入新的回忆场景。人物参考图决定身份、人数、左右关系和可辨识特征；用户明确的新场景、动作和构图可以覆盖原照片姿态，但不得改变人物身份。
- 用户没有明确指定新动作时，默认使用 `PHOTO_TO_GAME_ART`。

无论哪种模式，`references/style-images/` 中的 `18` 张固定图片只控制二维手绘画风、比例、线条、留白、平涂、背景和道具语言，不控制人物长相。使用前按 `references/style-reference-index.md` 查看全部原图。

## 2. 检查参考图

1. 查看原图，不凭缩略图猜测。
2. 确认人物数量、左右位置、脸部可见度和遮挡关系。
3. 若任一人物脸部严重遮挡、分辨率不足、多人对应不明确或不同照片互相冲突，先请用户补充清晰照片或说明对应关系。
4. 多张照片时，为每张图片标注用途和人物映射；不得把不同人物的特征合并。

## 3. 分别建立身份卡

固定使用 `CHARACTER.LEFT`、`CHARACTER.RIGHT` 等位置标签，不以“男生”“女生”代替位置标签。每人提取：

- `face_shape`：脸部长宽比、额头宽度、颧部宽度、下颌走向、下巴圆钝或收窄程度。
- `brows_eyes`：眉毛粗细与弧度、眼睛轮廓与倾斜方向、眼距关系；按组件规范简化，不生成写实虹膜。
- `nose`：鼻梁相对长度、鼻尖与鼻翼轮廓。
- `mouth_expression`：嘴唇厚薄关系、嘴角方向、露齿或闭口、酒窝和笑纹。
- `ears_marks`：耳朵外露程度，以及眼镜、胡须、痣、雀斑、耳饰等显著标记。
- `hair`：长度、分缝、刘海、发际线、蓬松度、外轮廓、发尾方向和发色。
- `skin_body`：两人的相对肤色、身高差、肩宽和体型。
- `clothing`：领型、袖长、版型、图案、服装主色和配饰。
- `pose_relation`：左右位置、朝向、视线、手势、身体接触、表情和亲密程度。
- `identity_anchors`：从以上特征中为每人选出 `4–6` 个最能区分真人的锚点；至少包含发型轮廓和脸型，不得全部来自服装。

## 4. 手绘转译规则

- 准确保留两人的脸型、五官轮廓、发型、发色、肤色和体型。
- 保留眼镜、胡须、痣、刘海、服装款式及服装主色等可辨识特征。
- 左右人物的特征必须分别绑定，不得交换发型、肤色、服装、配饰或面部特征。
- 卡通化后仍应能够看出角色分别对应参考图中的两个人。
- 不过度美化、换脸、改变年龄，不把两人生成相似的通用卡通脸。
- 在极简五官限制内，使用脸部长宽比、下颌轮廓、眉眼角度、鼻部长度、嘴角曲线、耳朵外露度和发型剪影表达差异；不得把两人的脸套用同一模板。
- 人物辨识为核心时使用半身或中近景，使逻辑画布中的可见脸高不小于 `40px`。服装颜色只能辅助辨识，不能作为相似度成立的唯一依据。
- 身份还原依赖剪影和相对比例，不依赖精细渲染。禁止为提高“相似度”添加双眼皮线、睫毛、虹膜高光、鼻翼阴影、皮肤明暗、嘴唇渐变、逐束发丝高光或写实手部；这些特征会把真人平均成半日漫 AI 脸。
- 判断头发长度时，先追踪头顶到最远可见发梢的连续整体剪影，再记录刘海与脸侧层次。脸侧短层次、发尾外翘、肩部遮挡或衣领重叠不得覆盖整体长短结论；越肩或垂至胸前的连续发块必须明确写入身份锚点。
- 服装有小花、圆点等微型纹样时，身份卡记录“底色＋纹样类型＋主色”，转译为 `8–18` 个不规则手绘图案、覆盖 `10%–25%`；纹样在衣缘和遮挡处截断，不等距满铺、不用同尺寸重复。纹样只辅助身份，不能压过脸型与发型。

## 5. 提示词身份块

存在人物参考图时，在完整生图提示词中加入以下已填写内容，不得保留空项：

```text
【人物参考图身份约束】
模式：PHOTO_TO_GAME_ART 或 IDENTITY_IN_NEW_SCENE。
输入角色：人物参考图控制身份；固定的 18 张风格参考图只控制画风。
CHARACTER.LEFT：位置、脸型、眉眼、鼻部、嘴形与表情、耳朵与显著标记、发型、肤色、体型、服装、身份锚点。
CHARACTER.RIGHT：位置、脸型、眉眼、鼻部、嘴形与表情、耳朵与显著标记、发型、肤色、体型、服装、身份锚点。
映射不变量：人数与左右关系准确；两人特征分别绑定；禁止串人、换脸、改变年龄、过度美化或通用卡通脸。
姿态规则：原照片转插画时保持姿态、表情和亲密关系；新场景模式按用户明确的新动作构图。
```

把人物参考图标注为“身份参考”；先逐张检查固定的 `18` 张风格原图，再按 `style-reference-index.md` 选择最多 `4` 张与任务最相关的独立风格图直接提交。若另有用户布局参考，则风格图最多 `3` 张。不得把身份图当风格图，也不得合并、删除或覆盖固定原图。

## 6. 出图验收与重试

逐人检查，不以“整体感觉相似”代替：

1. 人数、左右位置和人物映射完全正确。
2. 发型轮廓、发色、脸型和全部显著标记必须匹配。
   - 单独核对整体头发长度；不得把刘海或脸侧短层次误当成整体长度。
3. 每人至少再匹配眉眼走向、鼻部轮廓、嘴形/笑容、耳朵轮廓、肤色关系、体型、服装款式与主色中的 `4` 项。
4. 两人的脸、发型和服装不能互换，不能使用同一张通用卡通脸。
5. `PHOTO_TO_GAME_ART` 必须保持原图姿态、表情和亲密关系；`IDENTITY_IN_NEW_SCENE` 必须保持用户的新场景动作。
6. 人物外轮廓必须粗于内部五官、发丝和衣褶约 `1.9–2.3` 倍；脸、下颌、耳朵、颈肩、手臂、手掌、头发外缘、眼镜外框和衣服外缘统一使用人物外轮廓档。任一外缘变成细线，或出现半日漫眼睑、皮肤塑形和发丝高光，身份即使相似也判为失败。
7. 有服装纹样时，图案必须稀疏、不规则、服从衣缘和遮挡；出现贴图平铺、同尺寸重复或纹样穿透头发、手臂、道具即判为失败。

任一项失败时，列出失败的具体身份锚点，保持已正确的场景和组件不变，展示修订后的完整提示词并自动重试一次。重试后仍不可辨认时如实说明，不得宣称已经还原成功。
